# 마케팅 스킬 활용 가이드

스킬 본문은 원문(Corey Haines, MIT) 그대로다. **고치지 않았다.** 업스트림이 갱신되면 그대로 따라갈 수 있게 두었다.
이 문서는 그 위에 얹는 것 — 49개를 받아도 언제 무엇을 켤지 모르면 못 쓴다.

## 1. 시작은 하나뿐이다

새 프로젝트·새 클라이언트를 맡으면 **`product-marketing` 을 가장 먼저** 돌린다.
`.agents/product-marketing.md` 가 만들어지고, 나머지 스킬이 전부 이 파일을 참조한다.
이걸 건너뛰면 스킬마다 제품을 다르게 이해한 채로 결과물을 낸다.

## 2. 상황 → 켤 스킬

| 하려는 일 | 스킬 |
|---|---|
| 제품·시장 정의부터 | `product-marketing` → 그다음 전부 |
| 현황 진단 | `seo-audit` `cro` `competitor-profiling` `customer-research` |
| 계획 세우기 | `marketing-plan` `marketing-loops` `launch` |
| 웹사이트 문구 | `copywriting` `copy-editing` `offers` `marketing-psychology` |
| 콘텐츠·검색 | `content-strategy` `ai-seo` `programmatic-seo` `schema` `site-architecture` |
| 광고 | `ads` `ad-creative` `ab-testing` |
| 메일·문자·리텐션 | `emails` `sms` `onboarding` `churn-prevention` `referrals` |
| 측정·보고 | `analytics` `attribution` |
| 영업 | `prospecting` `cold-email` `lead-magnets` `pricing` `sales-enablement` |
| 관점을 여러 개 보고 싶을 때 | `marketing-council` |

## 3. 실전에서 걸린 것들

| 상황 | 겪은 일 | 대응 |
|---|---|---|
| 스킬이 안 켜짐 | "이거 마케팅 좀 봐줘" 같은 말로는 발동하지 않는다 | 스킬 이름의 트리거 단어를 문장에 넣거나 `/스킬명` 으로 직접 부른다 |
| 결과가 남의 회사 얘기 같음 | `product-marketing` 을 안 돌렸다 | 컨텍스트 파일부터 만든다 |
| 영어 톤이 그대로 나옴 | 원문이 영어권 SaaS 기준이다 | 한국 시장·소규모 팀 기준으로 다시 쓰라고 지시한다 |
| 스킬끼리 결론이 다름 | 각자 다른 가정을 세운 것 | 진단 → 계획 → 실행 순서로 하나씩. 동시에 여러 개 켜지 않는다 |
| 숫자가 그럴듯하게 지어짐 | 벤치마크를 요구했더니 만들어냈다 | 수치는 반드시 출처를 물어보고, 없으면 "없다"로 받는다 |

## 4. 이 스킬들의 한계

- **영어권 SaaS 전제**다. 채널(네이버·카카오·당근), 결제 관행, 개인정보 규정이 다르다
- 벤치마크 수치는 미국 기준이다. 그대로 목표로 삼지 않는다
- 실행 도구가 아니라 **사고 틀**이다. 실제 발행·집행은 별도로 붙여야 한다

## 5. 과제로 쓰는 법 (4단계 · 5단계)

1. 자기 업무에 가장 가까운 스킬 하나를 고른다
2. `SKILL.md` 를 열어 구조를 뜯는다 — frontmatter, 언제 발동하는지, 본문이 어떤 순서로 지시하는지
3. 같은 구조로 **내 업무 절차** 스킬을 쓴다
4. 실제로 발동하는지 확인하고 제출한다

원본을 고치는 것보다 구조를 베껴 내 것을 만드는 쪽이 과제에 맞다.
