# 디자인 스킬 활용 가이드

스킬 본문은 원문(Leonxlnx, MIT) 그대로다. **고치지 않았다.**
이 문서는 그 위에 얹는 것 — 어느 톤을 언제 켜는지, 그리고 켜면 안 되는 때.

## 1. 톤을 먼저 정하고 켠다

| 원하는 인상 | 스킬 |
|---|---|
| 기본기 (레이아웃·타이포·간격) | `design-taste-frontend` |
| 고급 에이전시 톤, 여백 크고 묵직하게 | `high-end-visual-design` |
| 담백한 편집 디자인, 파스텔·플랫 | `minimalist-ui` |
| 거칠고 강한 인상 | `industrial-brutalist-ui` |
| 기존 사이트를 끌어올리기 | `redesign-existing-projects` |
| 코드가 중간에 잘릴 때 | `full-output-enforcement` |

두 개를 같이 켜지 않는다. 톤이 섞이면 아무 인상도 남지 않는다.

## 2. 가장 중요한 규칙

**브랜드 규칙이 스킬 기본값을 항상 이긴다.**

이 스킬들은 각자 선호하는 색·폰트·그림자를 가지고 있다. 내 프로젝트에 정해둔 팔레트가 있으면
스킬이 제안하는 값이 아니라 내 토큰을 쓴다. 스킬 톤이 그대로 나가면 그게 "AI가 만든 티"다.

작업 순서:

1. 내 브랜드 토큰(색·폰트·간격 단위)을 먼저 문서로 고정한다
2. 스킬을 켠다
3. 결과에서 **내 토큰 밖의 값을 전부 걷어낸다**

## 3. 실전에서 걸린 것들

| 증상 | 원인·대응 |
|---|---|
| 어느 페이지나 비슷하게 생김 | 스킬 기본 톤을 그대로 받았다. §2 순서로 다시 |
| 그라데이션·큰 그림자가 남발됨 | 톤 스킬을 두 개 켰거나 브랜드 규칙이 없다 |
| 다크모드에서 글자가 안 보임 | 색을 미디어쿼리 안에서만 정의했다. 기본값을 먼저 정의한다 |
| 모바일에서 가로 스크롤 | 고정 픽셀 폭. 상대 단위와 `max-width: 100%` 로 |
| 코드가 중간에 끊김 | `full-output-enforcement` 를 같이 켠다 |

## 4. 과제로 쓰는 법

스킬 하나를 골라 **왜 이 규칙이 있는지**를 설명할 수 있을 때까지 읽는다.
"여백을 넓게"가 아니라 "본문 폭을 65자로 제한하면 시선 이동 거리가 줄어 읽기 속도가 올라간다" 수준으로.
그다음 내 프로젝트 톤 규칙을 같은 형식으로 쓴다.
