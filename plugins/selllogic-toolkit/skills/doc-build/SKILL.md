# 문서형 산출물 만들기

**CSS 를 문서마다 새로 쓰지 않는다.** 한 번 정한 셸(팔레트·폰트·표 스타일·인쇄 규칙)을 재사용한다.
문서마다 직접 쓰면 제안서는 골드, 리포트는 회색, 교안은 초록으로 갈라진다. 받는 사람은 그걸 본다.

## 1. 유형별 첫 장

문서는 첫 장에서 결론이 끝나야 한다. 읽는 사람은 끝까지 안 읽는다.

| 유형 | 첫 장에 오는 것 | 규칙 |
|---|---|---|
| 견적서 | 총액 + 단계 표 | **플로우 단계로 묶는다.** 기능·모듈로 쪼개면 고객이 항목을 뺀다 |
| 결과 보고서 | 결론 표 | 현황 나열 금지, 남 탓 어조 금지, 서술형 제목 금지 |
| 실행 제안서 | 결론 | 항목마다 목표·액션·비용·지표·다음액션. 장마다 결정할 것을 남긴다 |
| 교안 | 목차 | 슬로건 톤 금지. 인과 사슬을 먼저 세운다 |
| 포트폴리오 | **상대의 이익** | 자기소개가 아니다. 증거는 한 문장 |
| 내부 설계 문서 | 결론 표 | 설명 문단·강조 박스·불릿 산문 금지. **표와 도식만** |

## 2. 결과 보고서 구조

1. **핵심 성과** — 결과 불렛 3개. 표보다 **먼저**
2. **상세 변경 현황** — 구분 / 이전(문제) / 현재(결과) 3열 표
3. 기준·정책
4. 확인 위치
5. **화면 비교** — 캡처는 여기 한 섹션에 모은다. 흩뿌리면 결과가 산발적으로 읽힌다
6. 남은 확인

- 원인 설명 불렛이 장황함의 주범이다. 표의 '이전(문제)' 칸이 이미 원인을 말한다 → **별도 문단 금지**
- **결과 근거를 반드시 같이 낸다.** 화면을 못 찍는 항목은 적용된 문구를 텍스트로(스크린샷인 척 금지)
- 문장은 개조식(명사형 종결), 섹션 본문은 볼드 키워드 + 한두 문장

## 3. 수치 쓰는 법

이분 비교로 끝내지 말고 분포를 보고 구조를 말한다.

| 나쁜 예 | 좋은 예 |
|---|---|
| "A 7,460 vs B 4,435" | "일요일 평균 조회가 다른 모든 요일보다 높음. 일요일 9,316, 나머지 평균 5,839, 최저 월요일 4,835" |

거기서 한 걸음 더 간다. "가장 잘 읽히는 날에 가장 적게 발행하고 있다" 같은 구조 인사이트까지.

**발송 직전 원데이터로 재검증한다.** 원본이 갱신돼 옛 수치를 그대로 실어 보내는 사고가 흔하다.

**실측과 제안을 구분 표기한다.** 볼드 라벨로 (실측)/(진행 중)/제안. 상대 도메인은 상대가 더 잘 아니
단정형("신설합니다") 대신 제안 톤으로.

## 4. 금지 목록

| 금지 | 이유 |
|---|---|
| 전달물을 md 로 보내기 | 내부 소스만 md. 받는 사람에겐 PDF 또는 링크 |
| 파일명에 `_v2`·날짜·`(1)` | 버전은 git. 덮어쓰고 커밋한다 |
| em 대시 | 콜론·괄호·줄바꿈으로 |
| "저희"·"귀사"·수신자 호칭 | 문서 톤이 무너진다 |
| 비유·만연체 | 미완성은 "(구현 중)" 이라고 쓴다 |
| 추정 문장 | 미확정은 "확인 중" 한 줄 |
| 같은 내용을 도식과 표로 두 번 | 정보 많은 쪽만 남긴다(대개 표) |
| 배경·경위·비하인드 | 작업일지에 쓴다. 문서에 넣지 않는다 |
| 요약 재나열 섹션 | 본문과 중복이다 |
| "~판단이 우선입니다" 류 겸양 | 결론을 흐린다 |

## 5. 작업 순서

1. 유형 판정(§1) → **첫 장 결론부터** 쓴다
2. 본문을 마크다운으로 (표 중심, 산문 금지)
3. HTML 로 변환 → PDF 출력
4. **PDF 를 실제로 연다.** 파일이 생겼는지가 아니라 페이지를 본다
5. 내부 확인 후 발송
6. 리뷰는 **1라운드 후 정본 고정**. 이후엔 줄 단위 교체만. 3번째 재작업이면 텍스트가 아니라 레이아웃을 의심한다

## 6. 인쇄 함정

| 증상 | 해법 |
|---|---|
| PDF 에 표 음영이 안 나옴 | 배경 인쇄 옵션이 꺼져 있다. `print_background=True` |
| 표가 페이지 중간에서 잘림 | `page-break-inside: avoid` |
| 한글 줄바꿈이 어색 | `word-break: keep-all` |
| 폰트가 다른 PC 에서 깨짐 | 웹폰트를 임베드하거나 PDF 로만 전달 |
| 구버전 소실 | 개정 전 사본을 따로 남긴다 |

## 7. 마무리 체크

- [ ] 첫 장이 결론인가
- [ ] 표로 바꿀 수 있는 산문이 남아 있지 않은가
- [ ] PDF 를 실제로 열어봤나
- [ ] 파일명에 버전·날짜가 없는가
- [ ] 수치를 원데이터로 재검증했나
